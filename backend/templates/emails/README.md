# Шаблоны писем

Все семь транзакционных писем редактируются здесь без изменения Python.
Шаблонизатор — Jinja2. HTML автоматически экранирует динамические данные;
не используйте `|safe` для имён, названий событий, адресов или ссылок из данных.

## Что редактировать

Для каждого типа письма есть **один файл `<name>.htm`** с блоками Jinja:

- `subject` — тема письма; также используется в HTML `<title>`.
- `text` — текстовая альтернатива для клиентов без HTML. Меняя смысл HTML, обновите и её.
- `preheader`, `heading`, `introduction`, `content`, `footer` — видимая HTML-версия и оформление.

Тема и текстовая версия не выводятся в HTML. Рендерер читает их отдельно
из того же файла, без HTML-экранирования; HTML-версия автоматически экранирует данные.
Отдельных `.txt` в исходниках нет. Пример структуры одного письма:

```jinja
{% extends 'base.htm' %}
{% block subject %}Здравствуйте, {{ display_name }}{% endblock %}
{% block text %}Текстовая версия для {{ display_name }}.{% endblock %}
{% block heading %}Добро пожаловать{% endblock %}
{% block content %}<p>Здравствуйте, {{ display_name }}!</p>{% endblock %}
```

В `subject` и `text` используйте переданные переменные напрямую. Эти блоки
рендерятся отдельно от HTML, поэтому не зависят от HTML-макросов или `{% set %}` вне блока.

`base.htm` задаёт общую оболочку: бренд, фон, ширину, мобильные отступы и подвал.
`components.htm` содержит переиспользуемые таблицы деталей, уведомления, дату,
номер брони, склонение количества участников и контакт организатора.
`preview_index.htm` — галерея локального предпросмотра, она не отправляется получателю.

| Имя | Письмо |
|---|---|
| `reservation_confirmation` | Подтверждение бронирования, вложение `reservation.ics` |
| `reservation_cancellation` | Отмена брони администратором |
| `reservation_refund` | Оформленный возврат |
| `session_cancellation` | Отмена сеанса и брони участника |
| `session_deletion` | Удаление сеанса, CSV для администратора |
| `event_deletion` | Удаление события, CSV для организатора |
| `password_reset` | Восстановление пароля |

## Контракт данных

В шаблоны передаются отдельные значения, а не ORM-объекты или секреты приложения.
Все перечисленные ключи соответствующего письма всегда присутствуют. Некоторые
значения могут быть `None` — предусмотрите подпись «Уточняется» или условный блок.
Отсутствующий/опечатанный ключ вызывает `StrictUndefined`, чтобы ошибка не скрывалась
за пустой строкой.

| Переменная | Тип | Письма |
|---|---|---|
| `display_name` | строка; в `event_deletion` также `None` | Все, кроме `session_deletion` |
| `event_title` | строка или `None`, если связанное событие недоступно | Все, кроме `password_reset` |
| `reservation_id` | целое или `None` | Все письма о брони и `session_cancellation` |
| `session_id` | целое или `None` | Все письма о брони, `session_cancellation`, `session_deletion` |
| `session_start` | `datetime` или `None` | Все письма о брони и `session_cancellation` |
| `place` | строка или `None` | Все письма о брони и `session_cancellation` |
| `contact_email` | строка или `None` | Все письма о брони и `session_cancellation` |
| `has_refund` | `bool`, платёж имеет статус `succeeded` | Все письма о брони и `session_cancellation` |
| `participants_count` | целое | Только `reservation_confirmation` |
| `amount` | `Decimal` или `None` | Только `reservation_refund` |
| `currency` | строка, например `RUB` | Только `reservation_refund` |
| `reset_url` | абсолютная URL-строка с персональным токеном | Только `password_reset` |
| `subject` | отрендеренная тема | Все HTML-шаблоны, добавляется рендерером |

«Письма о брони» в таблице: `reservation_confirmation`,
`reservation_cancellation`, `reservation_refund`. Дата приходит в том же времени,
что хранится в приложении; дополнительное преобразование часового пояса не делается.
`has_refund` — существующий сигнал по статусу платежа, а не подтверждение зачисления
денег на счёт клиента. Не обещайте конкретных банковских сроков.

Примеры Jinja:

```jinja
Здравствуйте, {{ display_name }}!
{{ session_start.strftime('%d.%m.%Y %H:%M') if session_start else 'Уточняется' }}
{% if has_refund %}Возврат оформляется.{% endif %}
```

Новый блок можно добавить в `.htm` через `{% block content %}...{% endblock %}`;
для нового поля в данных потребуется дополнить контекст в `email_service.py`.
Адресаты, токены и вложения формируются в Python, шаблоны управляют представлением.
Сигнатуры существующих функций отправки сохранены.

## Предпросмотр без отправки

Из корня репозитория:

```powershell
.venv/Scripts/python.exe -m backend.core.scripts.preview_emails
```

Откройте `.email-preview/index.htm`: там все письма в широком и мобильном размере.
Никакие письма не отправляются, реальные брони и SMTP не используются.
Данные для примера находятся в `SAMPLE_CONTEXT` скрипта предпросмотра.
Правки шаблонов подхватываются при следующем рендере; готовые файлы предпросмотра
нужно пересоздать командой выше. На сервер изменения попадают при обычном обновлении приложения.

Можно проверить одно письмо на собственных демонстрационных данных:

```powershell
.venv/Scripts/python.exe -m backend.core.scripts.preview_emails --template reservation_confirmation --data demo.json
```

`demo.json` переопределяет только нужные ключи примера:

```json
{"display_name": "Анна", "participants_count": 3, "session_start": "2026-11-28T18:30:00"}
```

Для почтовых клиентов используйте табличную структуру и inline-стили; медиазапрос
в `base.htm` только дополняет основное оформление. Не добавляйте JavaScript,
формы, внешние CSS или зависимость от загрузки шрифтов. Браузерный предпросмотр
не гарантирует идентичный вид во всех версиях Outlook/Gmail.
